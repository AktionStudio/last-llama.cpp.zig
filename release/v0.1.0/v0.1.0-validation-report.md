## Corrected development-repository isolation evidence

A separate Windows Sandbox run attempted bounded reads of the real development
metadata HEAD/config files and enumeration of refs. All failed because the host
development path was excluded from the VM filesystem. These are guest path-not-found
results, not host ACL denial results. No fake or empty metadata directory was used.
The exact binary ZIP was accessible, its SHA-256 matched, and extraction succeeded.
Complete entry inventories of both release ZIPs contain no .git path entries.
This inventory finding is not a blanket assertion about arbitrary embedded content.

Windows Application Control blocked the unsigned CPU worker. CUDA execution and
full runtime qualification were not performed inside Sandbox. The two evidence
sets must not be described as one execution environment or simultaneous proof.
See corrected-isolation-evidence.json in the evidence ZIP for the normalized
protected path, bounded operations, results and hash of the private raw record.

## Claim withdrawn and remaining limitation

Withdrawn: "development Git metadata ... were reversibly absent during
extracted-package execution" as applied to the real development Git directory.
The original rename map covered staging Git metadata, not the real directory.
The previous blanket "All requested gates were performed and passed" is withdrawn.

The stronger claim in frozen docs/RELEASE.md:51-54 requires hiding the dependency
repository during extracted-package execution and says unenforceable isolation
fails qualification. Runtime execution while the real development Git directory
is inaccessible remains UNQUALIFIED. This limitation affects that combined claim,
not the independent runtime checks or separate Sandbox exclusion results.
The frozen source and tag are unchanged; this report is the correction to the
release-specific qualification claims. Do not present v0.1.0 as meeting every row
of the original procedure. The existing tag predates this correction and does
not certify the withdrawn claim. No replacement tag was created.
